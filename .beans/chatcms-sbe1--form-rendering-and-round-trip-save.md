## Purpose

Render forms from the model and write the result back identically to the old
Quiqr. This epic carries the backwards-compatibility contract, so it is built
golden tests first.

## Scope

- `internal/forms`: load a content file into form values, and write form values
  back to front matter plus Markdown body, preserving key order, quoting style,
  date formats, list indentation and the body separator.
- Field renderers in `web/src/fields/` for text, date, select, image, textarea,
  Markdown body, list of items and collapsed groups, matching DESIGN.md
  section 5.6.
- A Markdown body editor with the toolbar from the design and a raw source
  toggle, defaulting to formatted editing.
- Field to preview linking: the focused field is outlined in the preview.
- The golden test harness in `test/fixtures/`, with goldens generated from the
  reference app, plus the `golden` check in `flake.nix`.
- Autosave with the sync indicator states, no Save button anywhere.

## Done when

- A load-and-save round trip with no edits is byte identical to the old Quiqr
  output for every fixture.
- A known edit per field type matches its golden.
- `internal/forms` is at or above 80% statement coverage.
- Acceptance test 3 from the briefing passes.

## References

## Progress

First of two changes shipped: `add-content-round-trip`, archived at `openspec/changes/archive/2026-10-21-add-content-round-trip`. Two capabilities specified and built: `content/document` and `content/serialisation`.

The backwards-compatibility contract is now proven rather than promised. `internal/frontmatter` reproduces js-yaml at its defaults in Go: the quoting decision, literal blocks with the right chomping, folding at a line width of eighty measured per nesting depth, null and empty forms, JavaScript key ordering, and the timestamp resolver that turns a bare date into a full ISO moment exactly as the reference does. 156 generated goldens pass; deliberately breaking the quote style fails 39 of them, so the comparison is real.

`internal/forms` maps a document onto a model field tree and back: section and nest with groupdata, pull with its group, accordion as a list of objects, leaf-array as a list of values, nesting to any depth, and the Markdown body as a field. 144 documents round trip byte for byte, twelve edits match the reference byte for byte, and an edit to one field changes exactly one line.

Goldens are generated by running js-yaml 4.1.0 and tomlify-j0.4 3.0.0 themselves, via `scripts/generate-goldens.sh`, which is never part of the gate. The versions are recorded alongside the output.

One deliberate deviation: the reference writes TOML front matter with the closing delimiter on the same line as the last value, which its own reader cannot find. Verified by running both halves of the reference against each other, and recorded as a test that fails if a future version fixes it. ChatCMS reads TOML and JSON and refuses to write them, naming the format, rather than producing files neither application can open.

One correction to an already shipped package: `model.Field.GroupData` was a plain bool and could not tell an absent `groupdata` from a false one, which the section nesting rule depends on. It is now a pointer with a `GroupsData()` helper.

Coverage: `internal/forms` 91.8%, `internal/frontmatter` 84.9%, overall 84.2%. Only `internal/policy` is still absent from the core set.

Still open on this epic: the browser side. Field renderers, the Markdown body editor, field to preview linking and autosave belong after the design foundation epic ships, and a second change closes this bean.

## Summary of Changes

The editor works. A page opens as a form built from the site's own Quiqr
model, every field type is drawn, and what is typed is saved by itself and
written back byte for byte apart from what changed.

**The browser is given controls with values and a path for each, not the
model.** Working a path out means knowing that a grouping field may or may
not group its data, which `internal/forms` already knows. Sending the model
would mean writing those rules twice, in two languages, and having them
drift.

**A field this version cannot draw is shown as text, saying so.** Leaving it
out would make a page look emptier than it is and lose what was in it on the
first save. A test walks a model with a field nobody has implemented and
checks it is both shown and saved.

**A page's text is editable only where the model declares a field for it**,
which is how the reference implementation works. Where it does not, the text
is still shown and an attempt to write it is refused with a reason rather
than quietly dropped. The first run of this drew that field twice, once as an
ordinary control and once as the text editor; it is now drawn once.

**No Save button.** An edit is held for a moment and written when typing
stops, so a sentence is one save rather than forty, and whatever is waiting
is written when the screen goes away.

Three findings worth recording:

- A model with a mistake in it was reported as a site with no model at all.
  The parser already names the file and the field; that now reaches the
  person who has to fix it.
- My expectation that clearing a field removes the key was wrong. The
  reference writes an absent value, `internal/forms` already does that, and
  the contract wins over the hunch.
- Two buttons in the list controls shared an accessible name with their
  fields. Disambiguated by role rather than by changing the words.

One interface-check change: a colour a content creator picks is the site's
colour, not this interface's, so a token would be the wrong thing entirely.
The check gained a marker for that, which has to name whose colour it is.

Browsing, creating, renaming and deleting pages is the next epic, which this
one unblocks, as does live preview.

Coverage 84.1% overall, `internal/content` 82.9%, `internal/forms` 91.8%.
